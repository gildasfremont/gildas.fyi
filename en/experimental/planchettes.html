Turning a picture into a plank construction, and its instructions for a five-year-old

Claude invents the model, a program checks that it stands up and draws wordless instructions

November 25, 2026, in one day · Python · built with Claude Code · full write-up (Markdown)

Identical wooden planks, 1 × 3 × 15, can become anything, but a four- or five-year-old can't read written instructions yet, and drawn instructions only exist for a handful of models. I wanted to hand over any picture, the Eiffel Tower or a village church, along with the number of planks we have, and get back one black-and-white A4 page, without a single word, that the child can follow alone.

Claude looks and inventsIt recognizes the subject, looks for what makes it recognizable (the silhouette, the proportions, the parts) and writes the construction as text, plank by plank, step by step.
The program judges and drawsDeterministic, it checks that nothing overlaps, that everything stands up, that each plank has a reference to be placed right, and that the count fits the box. Then it draws the instructions.

The model is a text file you read like instructions (its keywords are in French). The unit is the thickness of a plank; one line places one plank, flat, on its edge or upright, and repeter repeats the step with an offset:

nom: Le pont

etape        # the walkway, on the floor: it sets the gap between the piers
plat-x 0 -3 0

etape        # the two piers
plat-y 0 0 0
plat-y 12 0 0
repeter 6 0 0 1   # 6 times, one thickness higher each time

The program is plugged into Claude through an MCP server with four tools: verifier (check), which reports every problem at once with the model line at fault, voir (see), which renders the finished model, notice, which makes the PDF, and exemple, which shows models that work. Claude writes, checks, fixes, looks, and starts over until it stands and looks right.

Look like it first, be three-dimensional second

The first real test was the Eiffel Tower. The facade, 50 planks, had the monument's proportions: 2.7 times taller than wide, against 2.6 for the real one. The 3D version, 103 planks, got the four legs and the arches back, but turned squat, 1.2 times taller than wide, and looked less like it. Hence the principle written that same day: aim for volume, which you recognize by walking around it, but not at the cost of proportions. verifier and voir now report front and side proportions, to compare with the subject's, and a measure of volume.

Standing up is not the same as buildable

The Bibliothèque nationale de France fit in the box, 152 planks out of 195, but asked for far more than a five-year-old places in one go. verifier now suggests sessions, breaking at the end of a step or a block. It also gives age-based advice: an upright plank is a hard gesture, unless it leans against a plank already in place; pushed against an upright plank that nothing holds, it knocks the rest over like dominoes. Temporary planks, such as a spacer setting the gap between two legs of the Eiffel Tower, come out as soon as they're no longer needed, and the instructions show which way to slide them.

Gravity, first computed for straight planks, ended up in three dimensions, with friction, once roofs wanted to lean. A leaning plank tips until it rests on something, and the computation finds what physics says: propped against a wall, it holds from about 60°, like a ladder. Two planks placed together as an A hold at 64°; a single one falls. That's the church spire, in two pairs, with no post or crossbar. The first version balanced a bar on a post, centered by eye. The program accepted it; I caught it on the instructions.

By the end of the day, the project has 38 commits, 31 models, from a simple portal to a 245-plank fortress, and about 2,400 lines of Python. What would complete the journey is still missing: comparing the model's silhouette with the subject's in the photo, as a second numeric judge next to "it stands", and a page usable without Claude.
