Adjusting a page's typography from what you see

You drag a line, the average of where the lines end, and the CSS follows

An afternoon's prototype · TypeScript, Vite, no framework · built with Claude Code · full write-up (Markdown)

A typographer judges a paragraph by its ragged right edge: the line endings spread around an average position, and that average is set by adjusting the measure, the type size and the leading. In a site editor, you adjust CSS properties (margins, widths, sizes) without seeing what they do to that edge. Swisser lets you adjust what you see instead.

A pivot at 3:46 p.m.

Composing a page from a font Adjusting a page that exists 2:06 p.m. 3:46 p.m. 6:26 p.m.

The first idea came at it from the other end: a Markdown document and a font. The engine read the font's metrics (x-height, cap height, ascenders, descenders), derived a baseline grid from them, and compared it with the text the browser displayed, at three screen widths. The button in the demo overlays a grid of that kind. By 2:27 p.m., it was running.

It wasn't what I was trying to adjust. At 3:46 p.m., the pivot is written into the project's memory and six files are deleted, from the grid calculation to the font reader. The new version starts from an existing web page, saved and then pasted or dropped into the editor, because a remote site refuses to display inside a frame. The project had done without a framework from the start, so that it could measure the actual rendering and line the overlay up to the pixel.

The line was vertical

The brief called for a "horizontal green line," and in the same breath described an average of line endings, which can only be vertical. Claude tried to satisfy both.

The compromise didn't hold. The rule Claude drew from it stayed in the project's memory: when the word and the function contradict each other, follow the function.

By the end of the afternoon

At 6:26 p.m., the editor found ten text blocks on the sample page, and let you pick one and drag its line.
